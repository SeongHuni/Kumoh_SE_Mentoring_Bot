| **그래서 결국 성능은 하나도 안 올랐다는 건가요?** | **네, 수치는 그대로입니다. 대신 왜 안 되는지를 알아낸 게 이번 성과입니다.** |
| **그럼 이번에 한 게 뭔가요?** | **관행으로 쓰이는 두 기법을 검증해서, 우리 데이터에 안 맞는다는 근거를 만들었습니다.** |

# 1. Overlap (4~8쪽)

| 질문 | 한 줄 답변 |
| --- | --- |
| Overlap 쓰면 성능이 나빠지나요? | **아닙니다, 좋아지는 걸 확인 못 했다는 뜻입니다.** 일부 지표는 오히려 살짝 높았습니다. |
| 500토큰에서만 본 거 아닌가요? | **300·500·1000토큰과 재귀 분할까지 4개 설정으로 재실험했고, 전부 차이 0.01 미만이었습니다.** |
| Overlap이 제대로 적용되긴 했나요? | **재귀 분할에서는 모든 경계에 100% 적용됐는데도 결과가 같았습니다.** |
| 그럼 Overlap은 쓸모없는 기법인가요? | **아닙니다. 1,000토큰 넘는 문서에서는 +0.100으로 효과가 나왔습니다.** 그런 질문이 23%뿐이라 평균에서 상쇄됐습니다. |
| 문서 특성 때문이라는 근거는요? | **같은 데이터를 문서 길이별로 나눠 재계산했더니 1,000토큰 기준으로 부호가 뒤집혔습니다.** |
| 7쪽 결과는 통계적으로 유의한가요? | **표본이 68개라 유의수준에는 못 미칩니다. 경향이 관찰됐다는 수준으로 보고 있습니다.** |
| 왜 문서 절반이 안 잘리나요? | **공지가 짧아서입니다. 길이 중앙값 445토큰인데 분할 기준이 500토큰입니다.** |
| Overlap 값을 200, 300으로 더 키워보지 그랬나요? | **150까지도 방향성이 없어서 더 키울 근거가 없다고 봤습니다.** 청크 수만 늘어납니다. |

# 2. 청킹 방식

| 질문 | 한 줄 답변 |
| --- | --- |
| 청킹을 AI(LLM)로 하나요? | **아닙니다, 규칙 기반입니다.** 빈 줄 → 목록 기호 → 문장 종결 어미 순으로 자릅니다. |
| 500토큰이 정확한 값인가요? | **자체 추정치입니다(tiktoken 아님).** 모든 실험에 동일 적용해서 비교는 유효합니다. |
| 왜 500인가요? | **지난 발표에서 10개 전략을 비교해 정했고, 문서 길이 중앙값 445와도 맞습니다.** |
| 재귀 분할이 뭔가요? | **문단 → 문장 → 공백 순으로 큰 경계부터 차례로 자르는 방식입니다.** |

# 3. 리랭킹 (9~10쪽)

| 질문 | 한 줄 답변 |
| --- | --- |
| Qwen3는 Recall@3가 올랐는데 왜 안 쓰나요? | **Recall@5는 오히려 0.013 떨어졌고, 2.2초 지연이 붙습니다.** 검색 자체가 3ms인데 너무 큽니다. |
| BGE는 왜 유독 나쁜가요? | **입력 길이 설정을 지정하지 않아 청크 뒷부분이 잘렸을 가능성이 있습니다.** 재검증 과제입니다. |
| 리랭킹을 영영 안 쓰나요? | **지금 보류입니다.** 설정 문제를 정리하거나 데이터가 다양해지면 다시 봅니다. |
| 다른 리랭커 모델은요? | **지금은 2개만 봤습니다.** 설정부터 정리한 뒤 후보를 넓힐 계획입니다. |
| 10쪽 가설은 검증된 건가요? | **아닙니다, 정황입니다.** 문서 유형별 성능 비교로 확인할 예정입니다. |
| 2.2초면 실제로 못 쓸 정도인가요? | **답변 생성에 이미 3초쯤 걸려서, 총 5초가 넘어가면 체감이 큽니다.** |

# 4. 평가 방법 (3쪽)

| 질문 | 한 줄 답변 |
| --- | --- |
| Recall@3이 뭔가요? | **정답 문서가 검색 상위 3개에 들어온 질문의 비율입니다.** |
| 0.6이면 낮은 것 아닌가요? | **정답 문서를 1개로 고정해서 셉니다.** 비슷한 공지를 가져와도 오답 처리됩니다. Recall@5는 0.74입니다. |
| 평가 데이터셋은 누가 만들었나요? | **자동 생성한 데이터셋입니다.** 사람이 하나씩 검수하진 않아서, 절대 점수보다 전략 간 비교용으로 봅니다. |
| Recall 말고 다른 지표는요? | **Recall@5와 MRR도 같이 봤고, 결론은 같았습니다.** |
| 답변 품질은 어떻게 평가하나요? | **이번엔 검색 정확도만 봤습니다.** 답변 품질은 프롬프트 전략과 함께 다음에 측정합니다. |

# 5. 프롬프트 전략 (11~12쪽)

| 질문 | 한 줄 답변 |
| --- | --- |
| 왜 프롬프트 전략이 필요한가요? | **지금은 "그럼 승인 안 되면?" 같은 후속 질문을 못 알아듣습니다.** |
| 규칙은 어떻게 정했나요? | **많이 쓰이는 RAG 프롬프트 사례를 조사해 1차 초안을 만들었습니다.** 이제 실패 사례로 다듬습니다. |
| 효과는 어떻게 검증하나요? | **같은 질문 세트로 프롬프트 수정 전후를 비교합니다.** |
| 근거가 없으면 어떻게 되나요? | **"확인할 수 없음"이라고 답하고 추측하지 않습니다.** |
| 공지와 후기를 왜 나누나요? | **일정·신청은 공식 공지가 근거여야 하고, 강의 후기는 참고 의견이라서입니다.** |
| 이미 구현된 건가요? | **아닙니다, 설계 초안 단계입니다.** 최종 발표까지 구현합니다. |

# 7. 전체 방향

| 질문 | 한 줄 답변 |
| --- | --- |
| 성능을 올리려면 뭘 해야 한다고 보나요? | **검색 알고리즘보다 질문 이해와 날짜·출처 필터링 쪽이 효과가 클 것으로 봅니다.** |
| 실패한 실험에 시간을 너무 쓴 것 아닌가요? | **검증 없이 넣었으면 근거 없는 복잡도만 남았을 겁니다.** 안 쓸 이유를 확보한 것도 결과라고 봅니다. |
| 다른 팀도 같은 결론이 나올까요? | **문서 성격에 따라 다릅니다.** 소설이나 논문처럼 문맥이 이어지면 Overlap이 유효할 수 있습니다. |
| 데이터를 더 모으면 달라지나요? | **출처가 다양해지면 리랭킹은 달라질 수 있다고 봅니다.** 지금은 학과 게시판이 76%입니다. |
