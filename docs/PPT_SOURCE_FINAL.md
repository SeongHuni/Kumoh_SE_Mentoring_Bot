## 슬라이드 4

**제목:** 이어지는 질문을 알아듣습니다

**핵심 메시지:** "그럼 승인 안 되면?" 같은 후속 질문을 독립형 질의로 바꿔 검색합니다

**데이터 — 동작 예시:**

| 사용자 | 시스템이 만든 검색 질의 |
| --- | --- |
| "수강지도 상담은 언제야?" | 수강지도 상담 일정 |
| → "그럼 승인 안 되면?" | **수강지도 상담 미승인 시 수강신청 제한** |

| 사용자 | 시스템이 만든 검색 질의 |
| --- | --- |
| "이정연 장학금 신청 어떻게 해" | 이정연 장학금 신청 방법 |
| → "그럼 수여식은 언제야?" | **이정연 장학금 수여식 일정** |

**데이터 — 처리 흐름:**

| 단계 | 하는 일 | 입력 |
| ---: | --- | --- |
| 1 | 후속 질문 → 독립형 질의 재작성 | 최근 대화 3쌍 + 현재 질문 |
| 2 | 검색 + 출처 분리(공지 / 강의평) | 독립형 질의 |
| 3 | 답변 생성 + 근거 번호 부착 | **현재 질문 + 검색 자료만** |

**시각화:**
- 가로 플로우 다이어그램
- **대화 이력이 1단계에만 들어가고 3단계에는 안 들어가는 것**을 화살표로 명확히 구분. 이게 이 장의 핵심

**발표 노트:**
- 대화 맥락을 쓰되, **어디에 쓸지를 분리**했습니다
- 검색 계획기는 대화를 읽어서 "무엇을 찾을지" 정합니다
- 하지만 **답변 생성기는 현재 질문과 검색 자료만 받습니다**
- 이렇게 하면 이전 답변에 오류가 있어도 다음 답변의 사실로 굳어지지 않습니다

## 슬라이드 5

**제목:** 모르면 되묻고, 범위 밖은 거절합니다

**핵심 메시지:** 추측해서 답하지 않도록 검색·생성 모델을 아예 호출하지 않는 경로를 뒀습니다

**데이터:**

| 상황 | 사용자 입력 | 시스템 동작 |
| --- | --- | --- |
| 대상이 둘 이상 | "수강신청 알려줘" → "장학금도" → "그거 마감은?" | **되묻기** — 검색·생성 호출 안 함 |
| 범위 밖 | "오늘 서울 날씨 어때?" | **거절** — 검색·생성 호출 안 함 |
| 근거 없음 | 관련 자료 없는 질문 | "자료에서 확인할 수 없습니다" |

**시각화:** 3행 표. "호출 안 함"을 강조색으로. 옆에 되묻기 화면 캡처(있으면).

**발표 노트:**
- 챗봇이 잘못 답하는 것보다 **모른다고 하는 게 낫다**고 판단했습니다
- 대상이 특정되지 않으면 추측해서 검색하지 않고 되묻습니다
- 이때는 검색도, 답변 생성도 아예 호출하지 않습니다. 틀린 답이 나올 여지를 없앤 겁니다
- 날씨·개인정보 같은 범위 밖 질문도 마찬가지입니다

## 슬라이드 6

**제목:** [핵심] 실험실에서 안 보이던 문제들

**핵심 메시지:** 지표는 괜찮은데 실제로 써보니 답을 못 하는 질문들이 나왔습니다

**데이터:**

| 발견한 문제 | 증상 |
| --- | --- |
| ① 분류 필터가 정답을 걸러냄 | "MT 수요조사" → 방산AI 부트캠프가 나옴 |
| ② 학과 대표 장학금이 안 나옴 | "장학금 신청 조건" → 이정연 장학금 주제 8위 |
| ③ 짧은 약어를 못 알아들음 | "MT 일정" → **TA 멘토** 프로그램이 1위 |
| ④ 후보를 너무 적게 가져옴 | 정답이 33위인데 후보는 30개까지만 |

**시각화:** 4행 표. 증상 열을 적갈색. 각 행 옆에 슬라이드 번호(7/8/9/10) 안내.

- 300문항 기준 Recall@5가 0.740입니다. 지표만 보면 나쁘지 않습니다
- 그런데 실제로 질문해보니 **당연히 나와야 할 게 안 나오는** 경우가 있었습니다
- 네 가지를 발견했고, 하나씩 원인을 찾아 고쳤습니다
- 지금부터 그 과정을 말씀드립니다

## 슬라이드 7

**제목:** 문제 ① — 분류 필터가 정답을 걸러냈다

**핵심 메시지:** 필터를 완벽하게 맞혀도 이득은 6.3pp인데, 틀리면 정답이 통째로 빠집니다

**데이터 — 측정 결과 (300문항):**

| 조건 | Recall@5 |
| --- | ---: |
| 분류 필터 없음 | 0.740 |
| 분류를 **완벽히** 맞혔을 때 (이론적 상한) | 0.803 |

**데이터 — 실제 실패 사례:**

| 질의 | 계획기가 고른 분류 | 정답 문서의 분류 | 결과 |
| --- | --- | --- | --- |
| "2학기 MT 수요조사" | 비교과·행사 | **학생회** | 정답 제외 |

같은 MT 주제가 `행정·안내`와 `학생회`로 흩어져 있어 **정확히 맞히는 것 자체가 불가능**했다.

**시각화:**
- 좌: 두 막대(0.740 vs 0.803), 차이 6.3pp를 화살표로
- 우: 필터 적용 전후 검색 결과 대비 (전: MT 공지 1~3위 / 후: 방산AI 부트캠프)

**발표 노트:**
- 검색 계획기가 질문을 보고 분류를 판단해서 필터로 걸고 있었습니다
- 그런데 "MT 수요조사"에서 계획기는 '비교과·행사'를 골랐는데, 그 공지는 '학생회'로 분류돼 있었습니다
- **정답이 후보에서 아예 빠졌습니다**
- 측정해보니 분류를 완벽히 맞혀도 이득은 6.3pp뿐이었습니다. 위험 대비 이득이 안 맞습니다
- 그래서 **분류 필터를 제거**했습니다. 출처 필터(공지 ↔ 강의평)는 성격이 명확하니 유지했습니다

## 슬라이드 8

**제목:** 문제 ② — 임베딩이 모르는 정보가 있다

**핵심 메시지:** "학과에서 이게 제일 중요하다"는 건 데이터에 없는 사람의 지식입니다

**데이터 — 문제 상황:**

"장학금 신청 조건" 질의에서 주제별 순위 (학과 장학금 27종)

| 순위 | 유사도 | 장학금 |
| ---: | ---: | --- |
| 1 | 0.610 | 석사우수장학금 |
| 2 | 0.546 | 외국어성적우수장학금 |
| **8** | **0.500** | **이정연 장학금** |

이정연 장학금은 학과 대표 장학금인데 8위까지 밀렸다.
석사우수장학금 공지에는 "백분위 87점 이상" 같은 조건 문구가 빽빽한 반면
이정연 공지는 서술형이라 "신청 조건"이라는 질의와 표면적으로 덜 닮았기 때문이다.

**데이터 — 해결: 점수 보정:**

```
최종 점수 = 유사도 + 이벤트 가중치 − 경과연수 × 0.012
```

| 문서 | 유사도 | 가중치 | 감쇠 | 최종 |
| --- | ---: | ---: | ---: | ---: |
| 이정연 2026 신청 안내 | 0.500 | **+0.050** | −0.005 | **0.545** |
| 이정연 2024 신청 안내 | 0.491 | +0.050 | −0.029 | 0.512 |

**시각화:**
- 상: 27종 중 8위를 보여주는 순위 막대
- 하: 보정 전후 top-5 대비 (전: 이정연 없음 / 후: 2위)

**발표 노트:**
- 임베딩은 "이 장학금이 학과에서 제일 중요하다"는 걸 모릅니다. 데이터에 없는 정보니까요
- 그래서 사람이 지정하는 가중치를 넣었습니다. 설정 파일 한 줄이면 됩니다
- **처음엔 +0.1을 줬는데 과했습니다.** top-5 중 4자리를 이정연이 차지했고, 그중 3개가 2024~2025년 옛날 공지였습니다
- 그래서 **가중치를 +0.05로 낮추고 시간 감쇠를 추가**했습니다. 오래된 공지는 연 0.012씩 감점됩니다
- 결과적으로 이정연 2026년 공지 하나만 2위로 올라오고, 나머지 자리는 다른 장학금이 채웁니다

## 슬라이드 9

**제목:** 문제 ③ — 짧은 약어를 못 알아듣는다

**핵심 메시지:** "MT"를 검색하면 "TA 멘토"가 나옵니다. 두 글자로는 임베딩이 구분하지 못합니다

**데이터:**

| 질의 | 1위 결과 | 유사도 |
| --- | --- | ---: |
| "MT 일정" | **TA 멘토 프로그램 안내** | 0.433 |
| "MT 수요조사" | MT 정식조사 (2·3위가 TA멘토) | 0.381 |
| "엠티" | 멘토링 공지 | 0.289 |
| **"학과 MT 일정"** | **MT 정식조사 안내** | **0.564** |

`"학과"` 한 단어가 붙는 순간 유사도가 **13pp** 오른다.

**데이터 — 해결: 질의 확장:**

| 사용자 입력 | 시스템이 만든 검색 질의 |
| --- | --- |
| "MT 언제야?" | 소프트웨어전공 학과 MT 일정 |
| "엠티 가?" | 소프트웨어전공 학과 MT 일정 |
| "과잠 신청" | 소프트웨어전공 학과 과잠바 신청 |
| "이정연 장학금 신청" | 이정연 장학금 신청 방법 *(이미 구체적이라 그대로)* |

**시각화:**
- 좌: "MT 일정" 검색 결과에 TA 멘토가 나오는 화면 (실패 사례)
- 우: 확장 후 정상 결과
- 중앙에 큰 숫자 **+13pp**

**발표 노트:**
- 이게 가장 의외였던 문제입니다
- `MT`와 `TA 멘토`를 헷갈립니다. 두 글자 약어는 임베딩이 잡아낼 신호가 거의 없어서, "일정·조사·프로그램" 같은 주변 단어가 점수를 지배합니다
- 사용자가 "학과 MT"라고 쳐야만 제대로 찾아졌습니다. 그건 서비스라고 할 수 없습니다
- 그래서 **검색 계획기가 짧은 약어에 맥락을 자동으로 붙이도록** 했습니다
- 이미 구체적인 질문은 건드리지 않습니다

## 슬라이드 10

**제목:** 문제 ④ — 후처리는 가져온 후보 안에서만 동작한다

**핵심 메시지:** 정답이 33위인데 후보를 30개만 가져오면, 가중치도 다양성도 손댈 대상이 없습니다

**데이터:**

| 항목 | 이전 | 수정 후 |
| --- | ---: | ---: |
| 검색 후보 수 | 30 | **100** |
| 검색 시간 | 583 ms | 161 ms *(측정 편차 범위)* |

이정연 장학금이 33위였는데 후보가 30개라 **가중치·다양성 로직이 아무 소용이 없었다.**
청크가 1,506개뿐이라 100개를 가져와도 검색 비용은 무시할 수준이다.

**데이터 — 참고: LLM이 실제로 인용하는 자료 (10문항 측정):**

| 자료 번호 | 인용된 문항 |
| --- | ---: |
| [1] | 10/10 (100%) |
| [2] | 5/10 (50%) |
| [3] | 2/10 (20%) |
| [4] | 2/10 (20%) |
| [5] | 1/10 (10%) |

문항당 평균 **2.0개**만 인용하지만, 뒤 순위가 결정적으로 쓰이는 경우가 30%였다.

**시각화:**
- 상: 후보 풀 30 → 100 확대를 도식으로. 33위 정답이 30 밖에 있는 그림
- 하: 인용 분포 막대 (1번이 100%, 급격히 감소)

**발표 노트:**
- 앞의 세 가지를 고쳤는데도 이정연 장학금이 안 나왔습니다
- 원인은 단순했습니다. **후보를 30개만 가져오는데 정답이 33위**였습니다
- 후처리는 가져온 후보 안에서만 동작합니다. 후보 밖은 손도 못 댑니다
- 후보를 100개로 늘리니 해결됐습니다
- 참고로 LLM은 top-5 중 평균 2개만 인용합니다. 그렇다고 k를 2로 줄이면 안 됩니다 — 30%의 질문에서 4번, 5번 자료가 결정적으로 쓰였습니다
