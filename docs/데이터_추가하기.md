# 새 게시글 추가하기

두 가지 경우를 다룬다.

1. **se게시판에 새 공지가 올라왔을 때** — 아래 "실행" 섹션. `scripts/collect/`가 API로 자동 수집한다.
2. **그 외 출처(다른 게시판, PDF, 손으로 정리한 자료 등)의 문서를 추가할 때** — 맨 아래
   "다른 출처의 문서 수동으로 추가하기" 섹션. 자동 수집기가 없으므로 스키마에 맞춰 직접 넣는다.

두 경우 다 결과물은 같다 — 코퍼스(`data/document통합파일...json`)에 문서가 늘고,
그걸 청킹·임베딩해서 Chroma에 넣으면 chroma-data가 새로 만들어진다.

---

## 실행

```powershell
npm run collect:fetch      # 1. 새 글 수집
npm run collect:convert    # 2. 코퍼스 형식으로 변환 + 분류 매핑
npm run collect:ingest     # 3. 청킹 → 임베딩 → Chroma 추가
```

2단계 결과(`outputs/new_posts_converted.json`)의 **분류가 맞는지 눈으로 확인한 뒤** 3단계를 실행한다.
확인만 하고 싶으면 `node scripts/collect/ingest-new-posts.js --dry-run`.

기준일을 바꾸려면: `SINCE=2026-08-01 npm run collect:fetch`
(기본값은 `2026-07-21`이며, 스크립트 상단 상수를 고치면 된다)

---

## 수집 방법

seboard.site는 **공개 REST API**를 제공한다. 인증도, HTML 파싱도 필요 없다.

| 용도 | 엔드포인트 |
| --- | --- |
| 목록 | `GET /v1/posts?categoryId=1&page=N&perPage=50` |
| 상세 | `GET /v1/posts/{postId}` — `contents`에 본문 HTML |
| 메뉴 | `GET /v1/menu` |

목록은 최신순이라 기준일 이전만 나오는 페이지에서 멈춘다. 요청 사이에 300ms 쉰다.

---

## 분류(category) 매핑

게시판이 주는 분류는 `일반 / Archive / 학생회` 3종뿐인데, 코퍼스는 11종 체계를 쓴다.
그래서 **제목 말머리 → 키워드** 순으로 매핑한다.

1. 제목 말머리 `[수업]`, `[학적]`, `[대학원]` 등 → `PREFIX_MAP`
2. 게시판 분류가 `학생회`면 그대로
3. 제목 키워드 → `KEYWORD_RULES` (제목을 본문보다 우선)
4. 본문 앞 400자 키워드
5. 아무것도 안 걸리면 `행정·안내`

### 규칙 순서가 중요하다

실제로 겪은 오분류 두 건이다.

- `"슈퍼컴퓨팅센터 전문직 모집 (연봉 4천이상)"` → 본문의 **"졸업생"**이 걸려 `학적·졸업`이 됐다.
  → 채용 키워드를 학적보다 **먼저** 판정하도록 순서를 바꿨다.
- `"디지털관 3,4층 쓰레기 배출 협조 요청"` → `연구·캡스톤`이 됐다.
  → 캡스톤 키워드를 좁히고 제목 우선 판정으로 바꿨다.

새 글을 넣을 때는 2단계 출력의 분류를 **반드시 눈으로 확인**할 것.

---

## 분류는 검색 필터로 쓰지 않는다

한때 검색 계획기가 판단한 분류로 필터를 걸었는데, **지금은 걸지 않는다.**

300문항으로 측정한 결과다.

| 조건 | Recall@5 |
| --- | ---: |
| 분류 필터 없음 | 0.740 |
| 분류를 **완벽히** 맞혔을 때 (이론적 상한) | 0.803 |

잘 맞혀도 이득이 6.3pp인데, 틀리면 정답 문서가 후보에서 통째로 빠진다.
실제로 `"2학기 MT 수요조사"` 질의에서 계획기가 `비교과·행사`를 골랐는데
해당 공지는 `학생회`로 분류돼 있어 정답이 제외됐다.
같은 MT 주제가 `행정·안내`와 `학생회`로 흩어져 있어 **정확히 맞히는 것 자체가 불가능**하다.

출처(se게시판 ↔ 에브리타임) 필터는 유지한다. 성격이 분명히 다르고 소속도 명확하다.

## 무엇이 갱신되나

3단계가 네 곳을 함께 갱신한다. 그래야 나중에 `npm run load`로 전체 재적재해도 복구된다.

| 대상 | 내용 |
| --- | --- |
| Chroma | 새 청크 증분 추가 |
| `data/document통합파일(에타리뷰분리).json` | 원본 코퍼스에 문서 추가 |
| `outputs/chunking_experiments/D_500/chunks.jsonl` | 청크 추가 |
| `outputs/chunking_experiments/D_500/embeddings.jsonl` | 임베딩 추가 |

`chunk_id`가 기존과 겹치면 실행을 중단한다(중복 적재 방지).

청킹은 `D_500`과 동일하다 — 500 tokens, overlap 0, 헤더 부착.

## 비용

문서 17건(청크 32개, 12,218토큰) 기준 **$0.0002**.
`text-embedding-3-small`이라 사실상 무시할 수준이다.

## 되돌리기

3단계 실행 전에 코퍼스를 백업해두면 안전하다.

```powershell
Copy-Item "data\document통합파일(에타리뷰분리).json" "outputs\corpus-backup.json"
```

Chroma를 되돌리려면 전체 재적재가 가장 확실하다.

```powershell
npm run load    # chunks.jsonl / embeddings.jsonl 기준으로 다시 채운다
```

## 다른 출처의 문서 수동으로 추가하기

se게시판 API로 안 들어오는 문서(다른 게시판, 공식 사이트, 손으로 정리한 FAQ 등)는
자동 수집기가 없다. 대신 **코퍼스가 쓰는 형식에 맞춰 직접 만들어 넣으면** 나머지
파이프라인(청킹 → 임베딩 → Chroma 적재)은 se게시판 문서와 똑같이 통과한다.

### 형식

문서 하나는 이 모양이다. 실제 예시 4건(출처별 하나씩)은 `data/sample_documents.json`에 있다.

```json
{
  "page_content": "제목: <제목>\n출처: <source>\n분류: <category>\n작성일: <YYYY-MM-DD 또는 빈 문자열>\n\n<본문>",
  "metadata": {
    "id": "<문서 전체에서 고유한 id>",
    "source": "se게시판 | 에브리타임 | 학과공식사이트 | 학사FAQ | ...",
    "sourceUrl": "https://... 또는 null (원문 링크 없으면 null)",
    "title": "<제목>",
    "author": "<작성자, 모르면 null>",
    "published_at": "YYYY-MM-DD 또는 null",
    "category": "<아래 11종 중 하나>",
    "crawled_at": "YYYY-MM-DD"
  }
}
```

- `page_content`의 앞부분(제목/출처/분류/작성일)은 `metadata`와 같은 값을 사람이 읽을 헤더로
  중복해 넣은 것이다 — 검색·답변 생성 모두 `page_content`를 그대로 쓰기 때문에 필요하다.
  헤더 없이 본문만 넣어도 되는데, 그러면 `node scripts/create-chunks.js`가 `metadata`를 보고
  자동으로 헤더를 만들어 붙인다 (`buildHeader()`, 기존 헤더가 있으면 건드리지 않는다).
- `id`가 기존 코퍼스와 겹치면 안 된다. 이미 있는 id로 넣으면 재적재 시 중복된다.
- `category`는 검색 필터로는 안 쓰이지만(검색 품질에 안 좋아서 뺀 결정, 위 "분류는 검색 필터로
  쓰지 않는다" 참고), 화면 표시·통계에는 쓰이므로 아래 11종 중 하나로 맞춘다.

  ```
  수업, 장학금, 행정·안내, 학적·졸업, 비교과·행사,
  취업·진로, 연구·캡스톤, 학생회, 대학원, 강의평, 기타
  ```

- `source`가 `에브리타임`이면 `분류: 강의평`으로 두고, **제목(`title`, `page_content`의 "제목:" 줄
  모두)을 `"<과목명> (<교수명>) 강의평 ..."` 형태로 맞춰야 한다** — `backend/app/rag.py`의
  `parse_review_title`이 정규식(`^(.+?)\s*\(([^)]+)\)\s*강의평`)으로 이 제목에서 과목·교수 이름을
  뽑아 답변의 출처 표시(`kind: "review"`)에 쓴다. 이 패턴에 안 맞으면 과목·교수 없이 그냥
  제목만 표시된다 (에러는 안 남).

### 반영 절차

```powershell
# 1. 새 문서를 배열에 이어붙인다 (JSON 배열 병합 — 직접 짜거나 스크립트로)
#    대상 파일: data/document통합파일(에타리뷰분리).json

# 2. 청킹 (D_500 기준 재생성)
node scripts/create-chunks.js

# 3. 임베딩 (본인 키로 비용 발생 — 문서 수에 비례, 문서 17건 기준 $0.0002 수준)
node scripts/embed-chunks.js D_500

# 4. Chroma 적재
npm run load
```

`data/document통합파일(에타리뷰분리).json`은 배열이고 `create-chunks.js`가 그 경로를
그대로 읽으므로, 새 문서를 그 배열 끝에 추가하기만 하면 된다. 원본은 실행 전에
백업해두는 걸 권한다 (위 "되돌리기" 참고).
