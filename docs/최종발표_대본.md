## 시작 전 점검 (발표 10분 전)

```powershell
cd "C:\Users\timjj\Desktop\26 여름 SIG\se_rag_chatbot"
docker compose ps
```

**PORTS를 반드시 본다.**

```
0.0.0.0:3000->3000/tcp   <- 정상
3000/tcp                 <- 게시 실패. 접속 안 됨
```

`0.0.0.0:...->` 가 없으면 다른 프로그램이 그 포트를 쓰는 중이다. 끄고 다시 만든다.

```powershell
docker compose up -d --force-recreate frontend
```

그다음 확인한다.

```powershell
curl http://localhost:8787/api/health     # indexed_chunks 가 1549
start http://localhost:3000               # 화면이 뜨는지
```

시연 질문 하나를 미리 던져본다. **첫 질문은 모델이 깨어나느라 느리다.**

시연에 쓸 4문항(학생회비/후속질문/되묻기/거부)을 **실제로 한 번씩 다
쳐본다.** 프롬프트는 계속 다듬는 대상이라, 어제 되묻던 질문이 오늘은
바로 답할 수 있다(실제로 "장학금"이 그랬다). 대본에 적힌 질문 그대로
지금도 같은 반응이 나오는지 직접 확인한다.

### 슬라이드 7 — Overlap은 왜 안 통했나 (90초) ★ 핵심

**이 프로젝트에서 가장 오래 붙잡은 문제입니다.**

Overlap은 RAG 교과서의 기본입니다.
"안 씁니다"라고 발표하려면 이유가 필요했습니다.

*(반전 1)* 처음엔 구현 버그였습니다. overlap이 경계의 15~30%에만 적용되고 있었습니다.
고쳐서 84~85%까지 올렸습니다. **그런데도 성능이 오르지 않았습니다.**

*(반전 2)* 그래서 "문서가 안 잘리니까 의미가 없다"고 설명했습니다.
그런데 측정해보니 **41.6%가 실제로 분할**되고 있었습니다. 제 설명이 틀렸습니다.

*(반전 3 — 천천히)* 그래서 절단면을 직접 셌습니다.
근거 문장이 청크 경계에 걸린 경우가 **96건 중 1건**이었습니다.
그리고 overlap은 **그 1건을 복구했습니다. 복구율 100%입니다.**

> **overlap은 제대로 작동했습니다. 작동할 기회가 거의 없었을 뿐입니다.**

공지글은 소설과 달리 문단이 독립적이라, 잘려도 근거 문장 자체가 쪼개지는 일이 드뭅니다.

*(반전 4)* 덧붙이면 "헤더가 17.5퍼센트포인트 기여한다"는 저희 수치도
다시 측정했을 때 재현되지 않아 철회했습니다.

**"소설이 아니라서"라는 막연한 설명 대신 96건 중 1건이라는 숫자를 찾는 데 시간을 썼습니다.**

### 슬라이드 8 — 평가셋 자체를 의심하다 (60초) ★ 천천히

발표를 준비하다가 팀에서 지적이 나왔습니다.
**"300문항도 사람이 만든 데이터가 아니라 편향이 있을 수 있다."**

확인해보니 맞았습니다.

*(표)*
질문에 문서 제목이 그대로 들어간 비율이 32.6%,
**근거 문장이 질문에 거의 그대로 등장한 비율이 81.3%**였습니다.

쉽게 말하면 **질문 안에 답이 들어 있었습니다.**

그래서 "사람이 만든 300문항"이라는 표현을 전부 걷어냈고,
이후 두 가지 원칙을 세웠습니다.

**하나, 절대 수치를 주장하지 않습니다.** "정확도 몇 퍼센트"라고 말하는
대신, 같은 평가셋으로 두 대안을 잰 **상대 비교**로만 씁니다. 잣대가
편향돼 있어도 그 위에서 A안과 B안 중 무엇이 나은지는 그대로 유효하기
때문입니다.

**둘, 숫자보다 확실한 증거는 직접 돌려보는 것입니다.** 그래서 오늘
뒷부분에 실제 시연을 준비했습니다. 오늘 보여드리는 숫자와 시연,
둘 다 절대적인 증명이 아니라 저희가 신뢰할 수 있다고 판단한 최선의
근거라는 점을 먼저 말씀드립니다.

### 슬라이드 9 — 검색이 안 되던 것들 (60초)

측정하고 고치기를 반복했습니다.

이정연 장학금이 검색되지 않아서 봤더니, 정답이 33위인데 저희는 30개만 가져오고 있었습니다.
MT를 물으면 TA 멘토 프로그램 공지가 먼저 나왔습니다. "학과"를 붙여 13퍼센트포인트 올렸습니다.

마지막 것이 재미있습니다.
"학생회비는 얼마야?"라고 물으면 2024년 공지가 나왔습니다.
검색 질의가 **"학생회비 금액"**이었는데, **"금액"은 공지 제목에 쓰지 않는 말**입니다.
**"학생회비 납부"**로 바꾸니 정답이 11위에서 1위로 올라왔습니다.

**공지 게시글을 검색하는데 일상어로 물으면 제목과 어긋납니다.**

### 슬라이드 10 — 같은 접두어가 반대로 작동하다 (50초)

그런데 여기서 모순이 생겼습니다.

MT에서는 "학과"를 붙여서 13퍼센트포인트를 얻었는데,
현장실습에서는 **같은 접두어가 정답을 밀어냈습니다.**

*(표)*
"현장실습 관련 공지"로 찾으면 정답이 1~3위인데,
"소프트웨어전공 현장실습 관련 공지"로 바꾸면 상위 5개 중 3개가 학과 소개 문서로 채워집니다.

자료가 전부 한 학과 것이라 학과 이름에 변별력이 없고, 오히려 소개 문서가 딸려옵니다.

그래서 규칙을 **"그 말만으로 무엇인지 알 수 없을 때만 붙인다"**로 좁혔습니다.
MT, TA, 과잠은 붙이고 장학금, 현장실습, 공결은 붙이지 않습니다.

## 말할 때 주의

- **"저희가 틀렸습니다"를 피하지 않는다.** 그게 이 발표의 강점이다.
- 수치를 말할 때 **"이 평가셋 기준"**을 붙인다.
- 모르는 걸 물으면 **"확인해보지 않았습니다"**라고 답한다.
  리랭킹 `max_length`가 대표적이다.
- 시연에서 답변이 느려도 기다린다. 조급하게 새로고침하지 않는다.
