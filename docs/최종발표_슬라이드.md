## 슬라이드 4 — 파이프라인

```
질문
 ├─ ① 검색 계획기 ──── 되묻기 (모델 호출 없음)
 │                └── 범위 밖
 ├─ ② 질의 임베딩          ← 원문이 아니라 다시 쓴 질의
 ├─ ③ 검색 top-100         ← 분류 필터는 걸지 않는다
 ├─ ④ 중요도 가중치        ← 유사도 + 이벤트 − 경과연수
 ├─ ⑤ 최신 우선            ← 비슷한 것끼리만
 ├─ ⑥ 다양성 → top-5      ← 한 공지가 독차지 못하게
 ├─ ⑦ 답변 생성
 └─ ⑧ 출처 표시            ← 실제 인용된 것만
```

**말할 것**
검색 계획기가 가장 많은 판단을 합니다. 원칙은 하나입니다 —
**이전 대화는 "무엇을 찾을지" 정하는 데만 쓰고, 사실의 근거로는 쓰지 않습니다.**

**화면 구성:** 이 흐름도. 후속질문 예시를 아래 작게.
`"수강지도 상담은 언제야?"` → `"그럼 승인 안 되면?"`
→ 검색 질의 `"수강지도 상담 미승인 시 수강신청 제한"`

## 슬라이드 5 — 근거 없으면 답하지 않는다

**증상**

```
질문: 휴학·복학·자퇴 전에 지도교수 상담이 필요한가요?
답변: 지도교수 상담은 필수가 아닙니다  ← 지어냄
근거: 수강신청을 위한 지도교수 상담 안내  ← 다른 절차
```

**확인** — 코퍼스에 휴학 제목 0건, **자퇴는 본문에도 0건**. 애초에 답할 자료가 없었다.

**고친 뒤**

| | 이전 | 이후 |
| --- | ---: | ---: |
| 환각 (자료 없는 질문) | 1/4 | **0/4** |
| 과잉거부 (자료 있는 질문) | 5/12 | **0/14** |

**말할 것**
규칙을 조이기만 했더니 이번엔 반대로 **답할 수 있는 질문 5개를 거부**했습니다.
공결 공지가 11건, 장학 공지가 48건 있는데도요.
그래서 "거부하면 안 되는 경우"를 반례로 함께 넣었습니다. 둘 다 있어야 균형이 잡힙니다.

**화면 구성:** 위 코드 블록 + 이전/이후 표.

## 슬라이드 7 — Overlap은 왜 안 통했나 (가장 오래 붙잡은 문제)

Overlap은 RAG 교과서의 기본이다. **안 쓴다는 결론을 발표하려면 이유가 필요했다.**

| | 무슨 일이 있었나 |
| --- | --- |
| **반전 1** | overlap이 경계의 15~30%에만 적용되는 **버그**를 발견. 고쳐서 84~85%로 올림. **그래도 성능이 안 올랐다** |
| **반전 2** | "문서가 안 잘려서 무의미하다"고 설명했는데, 측정하니 **41.6%가 실제로 분할**됨. 가설 기각 |
| **반전 3** | 절단면을 직접 셈 → **근거 문장 96건 중 경계에 걸린 건 1건**. overlap은 그 1건을 **100% 복구**했다 |
| **반전 4** | "헤더가 +17.5pp"도 재현 실패. "헤더가 overlap을 대체한다"는 가설도 절제 실험으로 반박 |

> **overlap은 제대로 작동했다. 작동할 기회가 거의 없었을 뿐이다.**

**말할 것**
공지글은 소설과 달리 문단이 독립적이라, 잘려도 근거 문장 자체가 쪼개지는 일이 드뭅니다.
"소설이 아니라서"라는 막연한 설명 대신 **96건 중 1건**이라는 숫자를 찾는 데 시간을 썼습니다.

**화면 구성:** 4단계 타임라인. 반전 3을 강조.

## 슬라이드 8 — 평가셋 자체를 의심하다

팀에서 지적이 나왔다. **"300문항도 사람이 만든 데이터가 아니라 편향이 있을 수 있다."**

| 편향 | golden_set | human_made_data |
| --- | ---: | ---: |
| 질문에 문서 제목이 그대로 들어감 | 32.6% | 18.2% |
| 근거 문장이 질문에 거의 그대로 등장 | **81.3%** | 2.9% |

확인해보니 맞았다. 그래서 이후로 두 가지 원칙을 세웠다.

> **원칙 1** — 절대 수치("정확도 92%")를 주장하지 않는다. 이 평가셋으로 잰
> **A안과 B안의 상대 비교**로만 쓴다. 잣대가 편향돼 있어도 같은 잣대로 잰
> 둘의 우열은 그대로 유효하다.
>
> **원칙 2** — 숫자보다 강한 증거는 **실제로 돌려보는 것**이다. 오늘 발표
> 뒷부분의 시연(슬라이드 13)이 이 지표들보다 신뢰할 수 있는 증거다.

**말할 것**
확인해보니 팀 지적이 맞았습니다. "사람이 만든 300문항"이라는 표현을
전부 걷어냈습니다. 그리고 이후 모든 수치에 "이 평가셋 기준"이라는 단서를
달았고, **절대값이 아니라 두 대안을 같은 잣대로 잰 상대 비교로만** 썼습니다.
오늘 보여드리는 숫자도 마찬가지입니다 — 그리고 숫자보다 확실한 증거는
뒤에서 직접 보여드릴 시연입니다.

**화면 구성:** 표 + 원칙 박스 2개. 이 슬라이드는 천천히.

## 슬라이드 12 — 서비스 형태로 정리

**백엔드를 Python 하나로 일원화**

Node와 Python 두 벌이던 서버를 FastAPI 하나로 합쳤다.
서버가 둘이면 규칙을 고칠 때마다 두 번 고쳐야 하고, 어느 쪽이 진짜인지 헷갈린다.

**Docker로 한 줄 실행**

```bash
docker compose up -d
```

세 서비스(프론트 3000 · API 8787 · Chroma 8000)가 함께 뜬다.
팀원은 Python이나 Node 버전을 맞출 필요가 없다.

**말할 것**
발표 전날 "제 PC에서는 안 돌아요"를 없애는 것이 목적이었습니다.
포트가 겹치면 Docker가 **조용히 실패**해서, 컨테이너는 떠 있는데 접속만 안 되는
상태를 세 번 겪었습니다. 그 진단법을 문서로 남겼습니다.

**화면 구성:** `docker compose ps` 출력 캡처.

## 슬라이드 13 — 시연

**보여줄 것 4가지**

| 질문 | 무엇을 보여주나 |
| --- | --- |
| `학생회비는 얼마야?` | 최신(2026) 공지를 [1]로 |
| `그럼 언제까지 내야 해?` | **후속질문** — 이력을 이어받음 |
| `신청 어떻게 해?` | **되묻기** — 선택지 제시 (사물함·과잠·장학금·현장실습 등) |
| `기숙사 통금 시간이 몇 시야?` | **근거 없으면 거부** |

> `장학금`처럼 주제어 하나만 있는 질문은 이제 되묻지 않고 바로 답한다
> (되묻기 A/B 측정 결과 반영, 슬라이드 7 참고). 시연 전 실제 화면으로
> `신청 어떻게 해?`가 여전히 되묻는지 재확인할 것 — 프롬프트는 계속
> 다듬는 대상이라 발표 직전 재검증이 필요하다.

**말할 것**
마지막 질문이 핵심입니다. **모른다고 답하는 것**을 보여드리겠습니다.

**주의:** 시연 전 `docker compose ps`로 PORTS에 `0.0.0.0:...->`가 있는지 확인할 것.

## 슬라이드 14 — 무엇을 배웠나

**1. 기본이라고 알려진 것도 우리 데이터에서 확인해야 한다**
Overlap은 RAG의 기본입니다. 그런데 우리 데이터에서는 작동할 기회가 없었습니다.
근거 문장 96건 중 1건. 이 숫자를 찾기 전까지는 "안 쓴다"고 말할 수 없었습니다.

**2. 고치면 반대쪽이 깨진다**
