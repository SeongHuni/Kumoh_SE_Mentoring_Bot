# 팀원 실행 안내

빈 PC에서 클론부터 실행까지 실제로 밟아보고 쓴 문서다.

---

## 미리 알아둘 것 — pull 만으로는 안 된다

검색은 `chroma-data/` 안의 벡터 DB(1,549청크)를 조회한다.
이 폴더는 **git 에 없다.** 26MB 바이너리라 데이터를 갱신할 때마다 통째로 바뀌어서
저장소가 계속 무거워지기 때문이다.

| 폴더 | 내용 | git |
| --- | --- | --- |
| `chroma-data/` | 검색이 실제로 조회하는 벡터 DB | **없음. 따로 받아야 한다** |
| `data/document통합파일...json` | 원본 코퍼스 907문서. 사람이 읽는 JSON | 있음 |

`chroma-data` 없이 실행하면 컨테이너는 뜨지만 검색 결과가 0건이라
모든 질문에 "자료에서 확인할 수 없습니다"가 나온다.

---

## 준비물

- **Docker Desktop** — https://www.docker.com/products/docker-desktop/
  설치 후 실행해서 고래 아이콘이 뜨면 준비 완료다.
- **`chroma-data.zip`** (27.7MB) — 팀에서 따로 받는다.
- **OpenAI API 키** — 답변 생성과 질의 임베딩에 쓴다.

Python 이나 Node 는 설치하지 않아도 된다. 컨테이너 안에 다 들어 있다.

---

## 1. 클론

```bash
git clone https://github.com/SeongHuni/Kumoh_SE_Mentoring_Bot.git
cd Kumoh_SE_Mentoring_Bot
git checkout integration/rag-service
```

## 2. chroma-data 넣기

받은 `chroma-data.zip` 의 압축을 **프로젝트 폴더 안**에 푼다.

zip 안에 `chroma-data` 폴더가 통째로 들어 있으므로, 프로젝트 루트에 풀면 된다.
결과가 이렇게 되어야 한다.

```
Kumoh_SE_Mentoring_Bot/
├── chroma-data/          <- 여기
│   ├── chroma.sqlite3    (26MB)
│   └── (UUID 폴더 3개)
├── backend/
├── frontend/
└── docker-compose.yml
```

`chroma-data/chroma-data/chroma.sqlite3` 처럼 두 겹이 되면 안 된다.

## 3. `.env` 만들기

프로젝트 루트에 `.env` 파일을 만들고 키 한 줄을 넣는다.

```
OPENAI_API_KEY=sk-...
```

`.env` 는 `.gitignore` 에 있어서 실수로 올라가지 않는다.
키는 이미지에도 구워지지 않고 실행할 때만 전달된다.

## 4. 실행

```bash
docker compose up -d --build
```

처음에는 이미지를 만드느라 3~5분 걸린다. 그다음부터는 `--build` 없이 뜬다.

**http://localhost:3000**

## 확인

```bash
curl http://localhost:8787/api/health
```

`indexed_chunks` 가 **1549** 로 나와야 한다. 0 이면 `chroma-data` 배치가 잘못된 것이다.

```json
{"status":"ready","indexed_chunks":1549,"collection":"sw_notice_d500", ...}
```

## 자주 쓰는 명령

```bash
docker compose ps               # 상태
docker compose logs -f backend  # 로그 (Ctrl+C 로 나감)
docker compose down             # 끄기
docker compose up -d --build    # 코드를 고쳤을 때
```

포트는 셋이다. **3000** 프론트, **8787** 백엔드 API, **8000** Chroma.
API 문서는 http://localhost:8787/docs 에서 볼 수 있다.

## 막히면

### 포트가 이미 쓰이고 있을 때

가장 흔한 문제다. `docker compose ps` 의 PORTS 를 본다.

```
repo-backend-1    8787/tcp                      <- 게시 실패
repo-backend-1    0.0.0.0:8787->8787/tcp        <- 정상
```

`0.0.0.0:...->` 가 없으면 **다른 프로그램이 그 포트를 이미 쓰고 있다.**
컨테이너는 떠 있는데 접속만 안 되는 상태라 알아채기 어렵다.

로컬에서 직접 띄운 것을 먼저 끈다.

```powershell
# 무엇이 잡고 있는지 확인 (Windows)
Get-NetTCPConnection -LocalPort 8787 -State Listen |
  ForEach-Object { Get-Process -Id $_.OwningProcess }
```

끈 다음 다시 만든다.

```bash
docker compose up -d --force-recreate backend
```

### "container name is already in use"

옛 컨테이너가 남아 있는 경우다.

```bash
docker rm -f chroma se-backend se-frontend
docker compose up -d
```

### 모든 질문에 "자료에서 확인할 수 없습니다"

`chroma-data` 가 없거나 경로가 한 겹 더 들어간 것이다.
`/api/health` 의 `indexed_chunks` 가 0 이면 이 경우다.

### 답변만 안 나오고 검색은 되는 것 같을 때

`.env` 의 키를 확인한다. 잔액이 떨어져도 같은 증상이 난다.

```bash
docker compose logs backend | tail -20
```

## 데이터를 새로 만들려면 (선택)

`chroma-data` 를 받지 않고 직접 만들 수도 있다.
청크 1,549개(`outputs/chunking_experiments/D_500/chunks.jsonl`)는 저장소에 있으므로
임베딩만 다시 만들면 된다. 본인 키로 약 $0.03 이 든다.

```bash
node scripts/embed-chunks.js D_500    # 임베딩 생성 (여기서 비용 발생)
npm run load                           # Chroma 적재
```

다만 **받아서 쓰는 쪽을 권한다.** 임베딩을 새로 만들면 값이 미묘하게 달라져
검색 순위가 어긋날 수 있고, 발표는 같은 데이터로 해야 한다.
