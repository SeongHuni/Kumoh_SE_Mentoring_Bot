# 후속 질문 처리 — 구현 완료

최종 발표 시연 항목 중 **"후속 질문 — 대화 맥락 반영"** 구현분이다.
설계는 `PROMPT_STRATEGY.md`, 구현은 아래 4개 파일.

---

## 실행 방법

```powershell
# 1. Chroma 서버 (둘 중 하나)
npm run chroma      # Docker 사용 시
npm run chroma:py   # Docker 없을 때 (Python chromadb)

# 2. 대화형 실행
npm run chat

# 3. 시연용 — 질문을 순서대로 자동 실행
npm run demo
node scripts/chat.js "자료구조 강의 어때?" "교수님은 어떠셔?"
```

명령어: `/reset` `/debug` `/history` `/help` `/exit`

---

## 구조

```
질문 + 대화 이력
      │
      ▼
 ┌──────────────┐   대화 이력은 여기서만 읽는다
 │  검색 계획기   │ ──► 독립형 질의 · 출처 · 분류 · 시점
 │ query-planner │ ──► 대상 불명확 → 되묻기 (검색·생성 호출 안 함)
 └──────────────┘ ──► 범위 밖 → 거절
      │
      ▼
 ┌──────────────┐
 │ Chroma 검색   │  출처/분류/연도 필터 적용
 └──────────────┘
      │
      ▼
 ┌──────────────┐
 │   후처리      │  최신 우선 재배치 · 문서 중복 제거
 └──────────────┘
      │
      ▼
 ┌──────────────┐   ※ 대화 이력을 넣지 않는다
 │  답변 생성    │      현재 질문 + 검색 자료만 받는다
 └──────────────┘
```

**핵심 분리** — 검색 계획기만 대화를 읽는다. 답변 생성기는 현재 질문과 검색 자료만 받으므로,
이전 답변에 오류가 있어도 다음 답변의 사실로 전파되지 않는다.

## 파일

| 파일 | 역할 |
| --- | --- |
| `scripts/chat.js` | 대화형 CLI · 시연용 스크립트 모드 |
| `scripts/lib/session.js` | 대화 이력 (최근 3쌍, 1,200토큰 상한) |
| `scripts/lib/query-planner.js` | 후속 질문 → 독립형 질의 재작성 |
| `scripts/lib/retrieval-postprocess.js` | 최신 우선 재배치 · 문서 중복 제거 |
| `scripts/lib/chroma-store.js` | (수정) 출처 여러 개를 `$in`으로 받도록 확장 |

## 동작 확인 결과

### 1. 후속 질문 — 대화 맥락 복원

```
질문> 수강지도 상담은 언제야?
  ↳ 질의: "수강지도 상담 일정" · 출처: 공식 공지 · 시점: 최신 우선
  → 2026-2학기 상담(7/27~8/5) 정확히 답변

질문> 그럼 승인 안 되면?
  ↳ 질의: "수강지도 상담 미승인 시 수강신청 제한" · 이전 대화 참조함
  → 미승인 시 수강신청 불가 정확히 답변
```

`"그럼 승인 안 되면?"`이 독립형 질의로 재작성됐다. 설계 문서의 예시와 일치한다.

### 2. 대상이 둘이면 되묻기 (fail-closed)

```
질문> 수강신청 일정 알려줘   → 검색·답변
질문> 장학금도 알려줘        → 검색·답변
질문> 그거 마감은?           → "어떤 장학금의 마감을 알고 싶으신가요?"
                              (검색·생성 모델을 호출하지 않음)
```

### 3. 범위 밖 요청 거절

```
질문> 오늘 서울 날씨 어때?
  → "학과 공지와 강의 후기 범위 안에서만 답변할 수 있습니다"
     (검색·생성 모델을 호출하지 않음)
```

### 4. 출처 자동 분리

```
질문> 자료구조 강의 어때?
  ↳ 출처: 학생 후기 → filters={"source":["에브리타임"]}
  → 에브리타임 강의평만 검색

질문> 교수님은 어떠셔?
  ↳ 질의: "자료구조 교수님에 대한 평가" · 이전 대화 참조함
  → 자료구조 맥락을 이어받음
```

## 구현하며 잡은 문제 3가지

### 계획기가 지나치게 되물었다

처음엔 `"그럼 승인 안 되면?"`에도 되물었다. 프롬프트가 *"대상이 하나로 특정되지 않으면 clarify"*로
모호했던 탓이다. 되물을 조건을 **세 가지로 명시**하고 반례를 넣어 해결했다.

- 이전 대화에 서로 다른 주제 후보가 둘 이상일 때
- 이전 대화에도 현재 질문에도 대상이 없을 때
- 개인정보·실시간 정보·범위 밖 요청일 때

### 오늘 날짜를 몰라 철 지난 답을 했다

`"수강지도 상담 언제야?"`에 2025-2학기를 답했다. 계획기 프롬프트에 **오늘 날짜를 주입**하고,
연도를 말하지 않은 일정 질문은 `latest`로 판단하도록 했다.

여기에 검색 후처리를 더했다. 유사도 차이가 **0.05 이내**면 관련도가 사실상 같다고 보고
게시일이 늦은 문서를 앞으로 보낸다. 이 임계값은 임의값이 아니라 측정치다 —
300문항에서 상위 1위와 5위의 유사도 차이 중앙값이 0.045였고, 55.3%의 질문이 0.05 이내에 몰려 있었다.

### 필터 충돌로 검색 결과가 0건이 됐다

계획기가 강의 후기 질문에 `category="수업"`을 골랐는데, 에브리타임 문서의 분류는 `강의평`이다.
`source=에브리타임 AND category=수업`이 되어 아무것도 안 나왔다.

프롬프트로만 막지 않고 **코드에서 차단**했다. `planToFilters()`가 route와 어긋나는 분류를 버린다.
필터는 과하게 걸면 0건이 되므로, 애매하면 거는 쪽이 아니라 빼는 쪽이 안전하다.
